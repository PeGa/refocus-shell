focus past — log and fix sessions

  focus past list [n] [--show-cycles]
  focus past add <project> <start> <end>
  focus past add <project> --duration 2h30m [--date YYYY/MM/DD]
  focus past modify <id> [project] [start] [end]              timestamped session
  focus past modify <id> [project] [--duration 2h] [--date YYYY/MM/DD]  duration-only session
  focus past modify <id> --notes                      rewrite the note
  focus past delete <id>

  focus past add refactor 14:00 15:30
  focus past add refactor --duration 2h30m --date 2026/09/03
  echo "shipped the parser" | focus past add refactor 14:00 15:30
  focus past modify 12 renamed --duration 3h
  focus past delete 12

  times       YYYY/MM/DD-HH:MM   14:30   "yesterday 14:00"   "2 hours ago"
  durations   1h30m   2h   45m

With no count, list shows the full history, newest first. Cycle breaks are
never listed as sessions; --show-cycles puts them back as boundary lines,
with the note you gave the break printed under it. See 'focus cycle --help'
for what a break is — 'cycle list'/'show' browse breaks and periods
directly, this page only decorates the plain log with them.

A duration-only session has no timestamps: modify can rename it, re-duration
or re-date it (--duration/--date, either or both, any order), but won't bolt
fake times onto it. --notes works on either kind.

One project name, one row: add or modify onto a name another session already
holds offers to append instead of creating a second entry — durations add
up, the note opens with the original's text, the dropped timestamps are
appended to it, and the folded-in row is deleted. Declining writes nothing;
`modify <id> --notes` never triggers this, since it touches neither name nor
timing.

Notes open in $EDITOR. To clear one, edit it and save empty — piping nothing
to `modify --notes` on a session that already has a note is a usage error,
not a silent clear.
